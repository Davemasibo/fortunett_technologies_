Status: tested locally; not deployed. Live records have not been modified.

Deployment:
1. Back up the live database and the existing files listed below.
2. Extract release.zip in the application root, preserving includes/ and super_admin/ paths.
3. Open Super Admin > Billing > an invoice > Edit invoice / view corrections.
   Opening the editor installs the audit table and manual_override column automatically.
   The application database user must have CREATE TABLE and ALTER TABLE permission.
4. For a manual payout: Super Admin > Collections > tenant payouts > Payout history > Correct entry.
5. Enter the corrected amounts and a reason, review the calculated total, then Save correction.

INVOICES BEFORE PAYOUT
Open Super Admin > Collections > tenant payouts > Settle invoices before payout.
Review all outstanding issued invoices, the deduction total, and the remaining balance.
Confirm and click Deduct invoices from collections, then record the remaining payout.
This settles only unpaid balances, including invoices not overdue yet. Previously paid
amounts are preserved. Insufficient funds or an in-flight payout rejects the batch atomically.
Manual payouts, tenant withdrawals and automatic payout submissions remain blocked until
all issued invoices are settled. This does not automatically debit invoices during a withdrawal.
A partially used collection remains held for a manual payout, following the existing queue behavior.
No live deductions have been made by preparing this release.

LATE COLLECTIONS AFTER EARLY INVOICE PAYMENT
Paid and part-paid invoices keep their recorded charges. At subsequent invoice generation,
unbilled hotspot commission from earlier frozen invoice periods appears separately as
Prior-period collections commission. It uses each source invoice's stored rate, not the
current plan rate. Existing carried charges are excluded to prevent duplicates.
Collection principal remains part of the tenant's payout balance; only commission is invoiced.
Fixed monthly/router fees are not repeated. SMS retains its existing unbilled-usage carryforward.
The carryover ledger records source invoice, target invoice, collection basis, rate and amount.
In Super Admin > Billing, open the earlier paid invoice and click Refresh current invoice.
This creates or refreshes the current editable invoice and links the historical breakdown.
A current invoice already paid/part-paid remains fixed; its still-unbilled difference is
picked up when an editable subsequent invoice is generated. Manual invoice charges remain
preserved while the carryover line updates on an otherwise unpaid invoice.
The schema upgrade adds carryover_amount and updates the generated total expression;
old invoice totals remain unchanged because existing carryover_amount defaults to zero.
Ghettolink live amounts have not been reconciled: production access is still blocked.
